# CAPÍTULO III: REQUIREMENTS SPECIFICATION

## 3.1. User Stories

| **Epic / Story ID** | **Title** | **Description** | **Acceptance Criteria** | **Related with (Epic ID)** |
| :--- | :--- | :--- | :--- | :--- |
| **EP01** | Behavioral Consistency | As a user, I want the system to monitor my nutritional adherence over time so that it can detect when I am at risk of abandoning my plan and act before I lose consistency. | | |
| US01 | Maintain Daily Nutritional Adherence | As a user with physical goals, I want the system to evaluate whether I met my daily nutritional targets so that my adherence status is always up to date and reflects my real consistency. | *Scenario 1: AdherenceStatus is updated to ON_TRACK after a successful day* <br><br> Given the user has logged all meals for the day and total calories consumed are within ±10% of the daily target <br> When the end-of-day evaluation runs <br> Then the system updates AdherenceStatus to ON_TRACK, increments the streak by one, and resets consecutive misses to zero <br><br> *Scenario 2: AdherenceStatus reflects a deviation when daily goal is exceeded* <br><br> Given the user's total caloric intake for the day surpasses the daily target by more than 10% <br> When the DailyGoalExceeded event is processed by BehavioralProgress <br> Then the system increments consecutive misses by one without resetting the streak yet and keeps AdherenceStatus as ON_TRACK until the 3-day threshold is reached <br><br> *Scenario 3: MealSkipped contributes to consecutive miss count* <br><br> Given a meal time window has passed without any MealRecord registered for that window <br> When the system detects the MealSkipped event <br> Then the system increments consecutive misses by one and sends a push notification asking the user if they forgot to log their meal | EP01 |
| US02 | Receive Early Warning Before Abandoning the Plan | As a user with a history of dropping nutritional plans, I want the system to detect when I have been inconsistent for 3 consecutive days so that I receive a preventive recommendation before I fully abandon my routine. | *Scenario 1: BehavioralDropDetected is triggered after 3 consecutive misses* <br><br> Given the user has accumulated 3 consecutive days of either MealSkipped or DailyGoalExceeded events <br> When the system evaluates the BehavioralProgress aggregate <br> Then AdherenceStatus transitions to AT_RISK, the streak is marked as broken, and a push notification is sent informing the user they have been off track for 3 days <br><br> *Scenario 2: A preventive recommendation is generated upon drop detection* <br><br> Given AdherenceStatus has just transitioned to AT_RISK <br> When the BehavioralDropDetected event is published to Smart Recommendation <br> Then the system generates a PreventiveRecommendation with a simple and achievable meal option aligned to the user's remaining macros and goal type <br><br> *Scenario 3: Push notifications for behavioral drop can be disabled from settings* <br><br> Given the user has disabled behavioral drop notifications in their profile settings <br> When BehavioralDropDetected is triggered <br> Then the system generates the preventive recommendation internally but does not send a push notification | EP01 |
| US03 | Prevent Nutritional Abandonment Through Intervention | As a user who has been inactive for an extended period, I want the system to escalate its intervention so that I receive a simplified reactivation plan that makes it easier to return without pressure. | *Scenario 1: NutritionalAbandonmentRisk is triggered after 7 days of inactivity* <br><br> Given the user has had no MealRecord registered for 7 consecutive days after BehavioralDropDetected was emitted <br> When the system evaluates the BehavioralProgress aggregate <br> Then AdherenceStatus transitions to DROPPED and an urgent push notification is sent with a supportive message inviting the user to return gradually <br><br> *Scenario 2: An intervention recommendation is generated for DROPPED users* <br><br> Given AdherenceStatus is DROPPED <br> When the NutritionalAbandonmentRisk event is published to Smart Recommendation <br> Then the system generates an InterventionRecommendation proposing a simplified version of the nutritional plan with reduced tracking requirements for the first three days <br><br> *Scenario 3: Intervention push notifications can be disabled from settings* <br><br> Given the user has disabled intervention notifications in their profile settings <br> When NutritionalAbandonmentRisk is triggered <br> Then the system generates the intervention recommendation without sending a push notification | EP01 |
| US04 | Recover Nutritional Consistency After a Drop | As a user who has been off track, I want the system to recognize when I resume logging meals so that my adherence progress is updated and I receive positive reinforcement that motivates me to continue. | *Scenario 1: ConsistencyRecovered is triggered on the first MealRecord after a drop* <br><br> Given AdherenceStatus is AT_RISK or DROPPED <br> When the user registers a MealRecord for the current day <br> Then the system transitions AdherenceStatus to RECOVERED and then to ON_TRACK, resets consecutive misses to zero, and sends a push notification celebrating the user's return <br><br> *Scenario 2: Adherence history reflects the recovery event* <br><br> Given ConsistencyRecovered has been emitted <br> When Analytics processes the event <br> Then the adherence history record is updated with the recovery date and the total days inactive during the drop period <br><br> *Scenario 3: Recovery push notification can be disabled from settings* <br><br> Given the user has disabled recovery notifications in their profile settings <br> When ConsistencyRecovered is triggered <br> Then the system updates the adherence history without sending a push notification | EP01 |
| US05 | Celebrate Consistency Milestones to Reinforce Habits | As a user building a nutritional routine, I want the system to recognize when I reach streak milestones so that I feel motivated to maintain the habit long term. | *Scenario 1: StreakMilestoneReached is triggered at 7 consecutive days* <br><br> Given the user has met their daily nutritional goal for 7 consecutive days <br> When the system evaluates the BehavioralProgress aggregate at end of day <br> Then StreakMilestoneReached is emitted and a push notification congratulates the user on their 7-day streak <br><br> *Scenario 2: Milestones are triggered at 14, 21, and 30 consecutive days* <br><br> Given the user continues meeting their daily goal beyond 7 days <br> When the streak count reaches 14, 21, or 30 <br> Then the system emits a StreakMilestoneReached event for each milestone and sends a distinct push notification <br><br> *Scenario 3: Streak resets to zero after a missed day* <br><br> Given the user has an active streak of any length <br> When the end-of-day evaluation determines the user did not meet their daily goal <br> Then the streak resets to zero and no milestone event is emitted | EP01 |
| US06 | Detect Strategy Mismatch to Protect Adherence | As a user whose metabolic targets have just been recalculated, I want the system to verify that the new targets are compatible with my adherence history so that I am not assigned a plan too aggressive for my real behavioral capacity. | *Scenario 1: StrategyMismatchDetected when new target exceeds adherence capacity* <br><br> Given MetabolicTargetsRecalculated has been emitted with a new daily caloric target significantly different from the previous one <br> When the system evaluates BehavioralProgress and finds historical adherence rate is below 60% <br> Then StrategyMismatchDetected is emitted and Smart Recommendation generates a GradualAdjustmentSuggested with a softer intermediate target <br><br> *Scenario 2: StrategyConsistencyConfirmed when new target is achievable* <br><br> Given MetabolicTargetsRecalculated has been emitted <br> When the system evaluates BehavioralProgress and finds historical adherence rate is 60% or above <br> Then StrategyConsistencyConfirmed is emitted and the new targets are applied without modification | EP01 |
| **EP02** | Nutrition Tracking | As a user, I want to record everything I eat each day with minimal friction so that my daily intake is always accurate and the system can validate my progress toward my nutritional goals. | | |
| US07 | Block Incompatible Foods Automatically to Eliminate Nutritional Risk | As a user with allergies or medical conditions, I want every food item I attempt to log to be automatically validated against my active restrictions so that I never accidentally consume something that puts my health at risk without relying on my own memory. | *Scenario 1: RestrictedItemBlocked prevents logging a food with a conflicting ingredient* <br><br> Given the user has lactose intolerance registered as an active dietary restriction <br> When the user attempts to log a food item that contains lactose <br> Then the system emits RestrictedItemBlocked, prevents the log entry from being saved, and sends a push notification identifying the conflicting ingredient and the restriction that triggered the block <br><br> *Scenario 2: Medical condition triggers nutritional risk flagging on food search* <br><br> Given the user has Type 2 Diabetes registered as a medical condition <br> When the user searches for food items <br> Then the system flags high glycemic index items in the search results with NutritionalRiskLevel HIGH and excludes them from all recommendations <br><br> *Scenario 3: No restrictions applied when profile has none configured* <br><br> Given the user has no dietary restrictions or medical conditions in their profile <br> When the user logs any food item <br> Then the system applies no filtering logic and stores the entry without restriction validation | EP02 |
| US08 | Find Accurate Nutritional Data to Make Informed Food Decisions | As a user tracking my nutrition, I want to search for any food by name against verified external databases so that the macro values I log are based on real nutritional data and not estimates that could silently break my caloric strategy. | *Scenario 1: Search returns matching results with full nutritional detail* <br><br> Given the user enters a food name as a search query <br> When the system queries Open Food Facts and USDA FoodData Central <br> Then the system returns a list of matching items each containing food name, serving size, calories, protein, carbohydrates, and fat <br><br> *Scenario 2: Restricted items are flagged to protect nutritional safety* <br><br> Given the user has active dietary restrictions configured <br> When the search results are returned <br> Then items containing restricted ingredients are flagged with the specific restriction that applies and with the corresponding NutritionalRiskLevel so the user can make a safe decision <br><br> *Scenario 3: No results returns an option to log manually* <br><br> Given the user submits a food name that returns no matches from either external database <br> When the empty result set is returned <br> Then the system informs the user that no match was found and offers a manual entry option | EP02 |
| US09 | Log a Meal to Maintain an Accurate Daily Intake Record and Validate Macro Progress | As a user with a nutritional goal, I want to add food items to my daily log by meal type with a custom portion so that my DailyIntake aggregate always reflects what I actually ate, my macro balance is recalculated in real time, and the system can determine whether I met or exceeded my daily target. | *Scenario 1: MealRecorded is emitted and macros are scaled to the entered quantity* <br><br> Given the user selects a food item, enters a quantity in grams, and assigns a meal category <br> When the user confirms the entry <br> Then the system stores the MealRecord, scales all macronutrients proportionally to the entered quantity, emits MealRecorded, and updates the daily macro balance in real time <br><br> *Scenario 2: DailyGoalExceeded is emitted when logging causes the total to surpass the target* <br><br> Given the user's cumulative daily intake is within target before the new entry <br> When the confirmed entry causes total calories to exceed the daily target by more than 10% <br> Then the system emits DailyGoalExceeded, sends a push notification indicating the exceeded amount in kilocalories, and the BehavioralProgress aggregate increments consecutive misses by one <br><br> *Scenario 3: Editing a logged quantity recalculates macros without affecting other entries* <br><br> Given the user has a MealRecord with an incorrect quantity <br> When the user updates the quantity <br> Then the system recalculates the macros for that specific entry only and re-emits MealRecorded to trigger a new daily macro validation <br><br> *Scenario 4: Deleting a log entry corrects the daily totals and re-evaluates goal status* <br><br> Given the user has a MealRecord they want to remove <br> When the user deletes the entry <br> Then the system removes the record, recalculates the DailyIntake totals, and re-evaluates whether the daily goal is met, on track, or exceeded | EP02 |
| US10 | Detect Meal Skips Automatically to Prevent Silent Adherence Losses | As a user with a structured meal schedule, I want the system to detect when I have not logged a meal during its expected time window so that skips are automatically counted toward my adherence evaluation and I cannot lose my streak without the system noticing. | *Scenario 1: MealSkipped is emitted when a meal window closes without a log* <br><br> Given the breakfast window (06:00–10:00) has closed without any MealRecord for that window <br> When the system evaluates the DailyIntake at 10:01 <br> Then the system emits MealSkipped for the breakfast window and sends a push notification asking if the user forgot to register their meal <br><br> *Scenario 2: MealSkipped increments consecutive misses and re-evaluates AdherenceStatus* <br><br> Given MealSkipped has been emitted <br> When BehavioralConsistency processes the event <br> Then consecutive misses are incremented by one and AdherenceStatus is re-evaluated against the 3-day threshold that triggers BehavioralDropDetected <br><br> *Scenario 3: MealSkipped push notifications can be disabled from settings* <br><br> Given the user has disabled meal skip notifications in their profile settings <br> When MealSkipped is triggered <br> Then the system emits the event for adherence evaluation but does not send a push notification | EP02 |
| US11 | Know at Every Moment Whether My Current Intake Is Keeping Me on Track | As a user tracking my daily nutrition, I want the system to always show me how far I am from my caloric and macro targets based on what I have logged so far today so that I can decide what to eat next without breaking my plan or unknowingly falling into a deficit or surplus that triggers a behavioral drop. | *Scenario 1: Remaining balance is recalculated after every MealRecord* <br><br> Given the user has at least one MealRecord for the current day <br> When the user logs a new meal entry and MealRecorded is emitted <br> Then the system immediately recalculates calories consumed, calories remaining, and individual macro balances for protein, carbohydrates, and fat against the daily targets set by the NutritionPlan aggregate <br><br> *Scenario 2: Net balance incorporates active calories from wearable sync* <br><br> Given the user has Google Fit connected and active calories have been synced for the day <br> When CaloricTargetAdjusted has been emitted by Metabolic Adaptation <br> Then the remaining calorie balance reflects the adjusted net target that includes active calories burned and not the original baseline target <br><br> *Scenario 3: Empty day shows full targets as available capacity* <br><br> Given the user has not logged any food for the current day <br> When the user checks their nutritional status <br> Then all consumed values are zero and the full daily targets are shown as the available capacity for the day | EP02 |
| US12 | Reduce Logging Friction by Photographing a Meal Instead of Searching Item by Item | As a user who eats varied meals and finds manual search tedious, I want to photograph my food plate and have the system estimate its nutritional content automatically so that the cognitive effort of maintaining my daily log does not become the reason I abandon my nutritional plan. | *Scenario 1: MealPhotoAnalyzed returns estimated food items and macros for Pro/Premium users* <br><br> Given the user is on a Pro or Premium plan and submits a clear image of a food plate <br> When the system forwards the image to Google Cloud Vision API and cross-references with Open Food Facts <br> Then the system returns a list of identified food items each with estimated quantity, calories, protein, carbohydrates, and fat <br><br> *Scenario 2: Confirmed scan result is stored as a MealRecord and triggers macro validation* <br><br> Given the system has returned a scan analysis result <br> When the user reviews the identified items, assigns a meal category, and confirms the entry <br> Then the system stores each identified item as a MealRecord, emits MealRecorded, and triggers the daily macro validation that evaluates whether DailyGoalMet or DailyGoalExceeded should be emitted <br><br> *Scenario 3: Unprocessable image rejects the scan and redirects to manual entry* <br><br> Given the user submits an image that is blurry, does not contain food, or cannot be processed <br> When the analysis completes <br> Then the system rejects the scan, informs the user that no food items could be detected, and directs them to the manual food search without losing the current day's log <br><br> *Scenario 4: Basic plan users are blocked from accessing Smart Scan* <br><br> Given the user is on a Basic plan <br> When the user attempts to access the Smart Scan feature <br> Then the system denies access and informs the user that Smart Scan requires a Pro or Premium plan | EP02 |
| US13 | Identify Which Specific Foods Are Breaking My Macro Balance | As a user who consistently misses one macro target, I want to trace back exactly which logged items contributed the most to the imbalance so that I can make precise substitutions instead of guessing what to change in my diet. | *Scenario 1: Meal detail returns each item with its individual macro contribution* <br><br> Given the user selects a specific meal category such as lunch <br> When the user requests the nutritional breakdown for that category <br> Then the system returns each registered food item with its name, quantity in grams, calories, protein, carbohydrates, and fat so the user can identify the specific item driving the imbalance <br><br> *Scenario 2: Consolidated meal summary shows whether the meal contributed to an exceeded target* <br><br> Given the user wants a quick summary without item-level detail <br> When the user requests a consolidated view of a meal category <br> Then the system returns the total calories and macros for that meal time and indicates whether that meal alone exceeded the recommended allocation for its time slot | EP02 |
| US14 | Identify Weekly Eating Patterns That Are Sabotaging Fat Loss Consistency | As a user focused on losing weight, I want to review which days and periods I consistently broke my caloric deficit so that I can detect the behavioral pattern behind my failures and correct it before it triggers a behavioral drop. | *Scenario 1: Weekly history returns daily calorie totals flagged against the deficit target* <br><br> Given the user requests their nutritional history for the past 7 days <br> When the system retrieves the DailyIntake records <br> Then the system returns the total calories consumed for each day, flags the days where the deficit was not maintained, and shows weekly macro averages <br><br> *Scenario 2: Monthly history surfaces recurring non-adherent days for pattern detection* <br><br> Given the user requests their nutritional history for the current month <br> When the system aggregates the DailyIntake records <br> Then the system returns the monthly caloric average, the total days where the deficit was maintained, and identifies which weekdays had the highest rate of DailyGoalExceeded events <br><br> *Scenario 3: Historical navigation allows reviewing any prior period* <br><br> Given the user wants to review a specific past week or month <br> When the user selects a prior time range <br> Then the system retrieves and returns the accurate nutritional data for that specific period | EP02 |
| US15 | Prevent Exceeding the Caloric Deficit Limit Before It Counts as a Behavioral Miss | As a user with a weight loss goal, I want the system to recalculate my remaining caloric capacity after every meal I log so that I always know exactly how much I can still eat before triggering a DailyGoalExceeded event that damages my streak. | *Scenario 1: Remaining deficit capacity is recalculated after every MealRecord* <br><br> Given the user has a caloric deficit target established by the NutritionPlan aggregate <br> When the user logs a meal entry and MealRecorded is emitted <br> Then the system immediately recalculates the remaining calories before the deficit limit is reached and updates the daily balance <br><br> *Scenario 2: DailyGoalExceeded emits a behavioral miss and notifies the user* <br><br> Given the user's cumulative intake surpasses their deficit target by more than 10% <br> When DailyGoalExceeded is emitted <br> Then the system sends a push notification with the exact kilocalories exceeded, increments consecutive misses in BehavioralProgress, and marks the day as a deviation | EP02 |
| US16 | Ensure Muscle Growth Conditions Are Met Through Daily Protein and Surplus Tracking | As a user focused on muscle gain, I want the system to continuously evaluate whether my protein intake and caloric surplus are sufficient for hypertrophy so that I never finish a day having unknowingly undermined my muscle synthesis conditions. | *Scenario 1: Protein compliance is shown as a real-time percentage of the hypertrophy target* <br><br> Given the user from the muscle-gain segment has a protein target of at least 2.0g per kg of body weight <br> When the user logs meals throughout the day <br> Then the system recalculates after each MealRecord the grams of protein consumed, the percentage of the target achieved, and the grams remaining to meet the muscle synthesis requirement <br><br> *Scenario 2: Insufficient surplus triggers a DailyGoalExceeded notification in reverse at end of day* <br><br> Given the user from the muscle-gain segment has a caloric surplus target and the day ends with total intake below the surplus threshold <br> When the end-of-day evaluation runs <br> Then the system identifies the caloric gap in kilocalories needed to have met the surplus, sends a push notification, and records the day as a deviation in BehavioralProgress | EP02 |
| US17 | Detect Recurring Macro Imbalances That Are Eroding Fat Loss Progress Over the Week | As a user focused on losing weight, I want the system to analyze my weekly macro distribution so that I can identify which recurring nutritional patterns are reducing my satiety or energy and are likely driving my adherence drops before they become a streak reset. | *Scenario 1: Weekly analysis identifies each day where the deficit was not maintained* <br><br> Given the user from the weight-loss segment has at least 5 logged days in the past 7 days <br> When the user requests the weekly macro analysis <br> Then the system returns each day's caloric total against the deficit target, flags specific days where the limit was exceeded, and shows the average daily deviation in kilocalories <br><br> *Scenario 2: Macro distribution breakdown surfaces patterns that explain satiety failures* <br><br> Given the user requests the weekly nutritional distribution <br> When the system calculates average macro percentages across logged days <br> Then the system flags any day where fat or carbohydrate intake deviates more than 15% from the recommended distribution and correlates those days with the DailyGoalExceeded events in the adherence history | EP02 |
| US18 | Identify Protein and Surplus Gaps That Are Blocking Weekly Muscle Synthesis | As a user focused on gaining muscle, I want the system to show me precisely which days I fell below my protein target or failed to maintain the caloric surplus so that I can identify the specific nutritional gaps preventing consistent muscle recovery and synthesis. | *Scenario 1: Weekly protein compliance flags each day below the hypertrophy threshold* <br><br> Given the user from the muscle-gain segment requests the weekly macro analysis <br> When the system evaluates each logged day against the protein target <br> Then the system returns protein consumed per day, flags days where intake fell below the minimum target, and calculates the overall weekly protein compliance as a percentage <br><br> *Scenario 2: Surplus stability report correlates irregular days with potential recovery deficits* <br><br> Given the user requests the weekly nutritional detail <br> When the system aggregates the caloric surplus or deficit for each logged day <br> Then the system identifies days where the surplus dropped below zero and returns the average surplus maintained across the week so the user can assess whether synthesis conditions were consistently met | EP02 |
